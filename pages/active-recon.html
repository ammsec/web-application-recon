Active Recon

Once passive sources are exhausted, active recon starts — every technique here sends real traffic directly to the target. This page is the hub for every phase that touches the target, from here on.

Active vs. Passive — what's the actual difference?

Passive recon (Phase 1) pulls information from third parties — Shodan, Censys, DNS databases — without the target ever seeing a single request from you. Active recon flips that: DNS brute forcing, HTTP probing, directory fuzzing, and vulnerability scanning all generate real requests the target's logs will see. Neither approach replaces the other — passive recon narrows the list, active recon verifies and digs into it.

Before You Start Sending Traffic

Scope & Authorization Read First

Only run active techniques against targets you're explicitly authorized to test — your own infrastructure, a bug bounty program's in-scope assets, or a client engagement with signed authorization. Sending scans to anything else is illegal in most jurisdictions, regardless of intent.

Rate Limiting Best Practice

Most tools in the active phases support a rate-limit flag (-rl, -t, --stable, etc.). Aggressive, unthrottled scanning can trip WAFs, get your IP blocked, or in the worst case degrade the target's service — which turns a recon exercise into a real incident. Start conservative and scale up only if the program's scope explicitly allows it.
