Introduction

Before touching any tool, it helps to know what "recon" actually means in the context of web application security — and why it's usually the difference between finding something real and finding nothing at all.

What is web application recon?

Reconnaissance is the information-gathering phase that comes before any actual testing. It's the process of mapping out everything a target exposes — subdomains, live hosts, technology stack, endpoints, parameters — before trying to break any of it. Most real vulnerabilities aren't found by throwing payloads at the first page that loads; they're found on the forgotten staging subdomain, the old API version, or the endpoint nobody remembered to secure. Recon is how those get found in the first place.

Who this guide is for

Bug bounty hunters

Looking to build a repeatable process for turning a single domain into a full list of tested attack surface.

Pentesters

Needing a structured, phase-by-phase checklist to run at the start of a web application engagement.

Security beginners

Learning how professional recon workflows are actually built, one phase at a time, with real commands instead of just theory.

How this guide is organized

The guide follows a strict order — each phase produces the input the next phase needs. Passive recon narrows down what to look at; everything after that gets progressively more active and more targeted, ending in a report someone else can act on.

A note before you start

Every active technique in this guide sends real traffic to a target. Only ever run these against systems you're explicitly authorized to test — your own infrastructure, an in-scope bug bounty asset, or a signed pentest engagement. See the Active Recon page for more on scope and rate limiting before moving past Phase 1.
