Phase 7 — JavaScript & Secrets Analysis

Dig through JavaScript files for hidden endpoints and hardcoded secrets — API keys, tokens, internal URLs, and credentials that developers accidentally shipped to production.

Why this phase matters

Frontend JavaScript ships to every visitor's browser, which means anything hardcoded in it is effectively public — even if it was never meant to be. API keys, internal endpoint paths, and AWS credentials show up here more often than you'd expect.

SecretFinder Python

What it does: Runs regex-based pattern matching against JavaScript files to catch API keys, tokens, and passwords.

GitHub ↗

Installation

git clone https://github.com/m4ll0k/SecretFinder.git
cd SecretFinder
pip3 install -r requirements.txt

Usage

# Scan a single JS file over HTTP
python3 SecretFinder.py -i https://target.com/app.js -o cli

# Scan a local file
python3 SecretFinder.py -i /path/to/file.js -o cli

# HTML output
python3 SecretFinder.py -i https://target.com/app.js -o results.html
jsluice Go · Modern

What it does: Performs static analysis on JavaScript files to extract URLs, endpoints, API keys, and secrets. Considered the modern replacement for SecretFinder.

GitHub ↗

Installation

go install github.com/BishopFox/jsluice/cmd/jsluice@latest

Usage

# Extract URLs from a JS file
jsluice urls target.js

# Extract secrets (API keys, tokens)
jsluice secrets target.js

# JSON output
jsluice urls target.js | jq .

# Fetch and analyze directly from a URL
curl -s https://target.com/app.js | jsluice urls
curl -s https://target.com/app.js | jsluice secrets

# Bulk — analyze every JS file from your URL list
cat cleaned_urls.txt | grep "\.js$" | xargs -I@ curl -s @ | jsluice urls
