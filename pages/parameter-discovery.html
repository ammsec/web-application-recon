Phase 8 — Parameter Discovery

Find hidden or undocumented parameters on discovered endpoints. These are frequently where XSS, SQLi, SSRF, and IDOR vulnerabilities actually live.

Why this phase matters

Documented parameters get tested by everyone. The ones that don't show up in the UI or the docs — debug flags, legacy fields, internal-only params — are far more likely to be untested and exploitable. Pulling these out opens up entirely new attack vectors on endpoints you already know about.

Arjun Python

What it does: Discovers hidden parameters across GET, POST, JSON, and XML methods against an endpoint. Ships with a built-in wordlist of 25,000+ parameter names.

GitHub ↗

Installation

pipx install arjun

# OR via pip
pip3 install arjun

# OR via apt
sudo apt install arjun

Usage

# Find GET parameters
arjun -u https://target.com/search

# Find POST parameters
arjun -u https://target.com/login -m POST

# JSON body parameters
arjun -u https://target.com/api -m JSON

# Custom wordlist
arjun -u https://target.com -w /path/to/wordlist.txt

# Multiple URLs from a file
arjun -i urls.txt

# Save output
arjun -u https://target.com -o results.json

# Export for Burp Suite
arjun -u https://target.com -oB

# Add delay to avoid rate limiting
arjun -u https://target.com --stable
ParamSpider Python · Historical

What it does: Pulls URLs that already contain parameters from the Wayback Machine — a fast way to surface parameter names that have been used historically, with zero active probing.

GitHub ↗

Installation

git clone https://github.com/devanshbatham/ParamSpider
cd ParamSpider
pip3 install -r requirements.txt

Usage

# Basic usage
python3 paramspider.py -d target.com

# Include subdomains
python3 paramspider.py -d target.com --subs

# Save to file
python3 paramspider.py -d target.com -o params.txt
