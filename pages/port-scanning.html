Port Scanning

Look past the web server. Open ports, running services, and exposed non-HTTP protocols often reveal a bigger attack surface than the website itself.

Why this phase matters

Recon so far has focused entirely on HTTP/HTTPS. But a host can also expose SSH, FTP, databases, admin consoles, or internal services on non-standard ports — often with weaker security than the public-facing site. A port scan is how you find those before moving into deeper testing.

Nmap C · Industry Standard

What it does: The standard network scanner — finds open ports, identifies running services and their versions, detects the OS, and can run vulnerability-detection scripts against what it finds.

GitHub ↗

Installation

sudo apt install nmap

Usage

# Basic port scan
nmap target.com

# Common web ports
nmap -p 80,443,8080,8443,8888,3000,5000 target.com

# Full port scan — all 65,535 ports
nmap -p- target.com

# Service version detection
nmap -sV target.com

# OS detection
nmap -O target.com

# Script scan — includes vulnerability detection
nmap -sC -sV target.com

# Fast scan (top 100 ports only)
nmap -F target.com

# Save output
nmap -sC -sV target.com -oN nmap_results.txt

A note on scan intensity

A full -p- scan against a whole subdomain list can take a very long time and generates a lot of traffic. Reserve it for a small set of high-value targets, and use the common-ports or fast-scan modes when scanning a large host list.
