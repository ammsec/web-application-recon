Recon for Web Application

Web Application Recon Checklist

Recon Pipeline

This page explains the full recon workflow step by step. Each phase includes an overview, tools, example commands, output, and tips.

Phase 1 — Passive Recon & OSINT

Collect publicly available information before interacting with the target. This helps identify domains, technologies, employees, certificates, and historical URLs.

Recommended Tools

  • theHarvester
  • crt.sh
  • Amass
  • Subfinder
  • Waybackurls
  • GAU

Example Pipeline

subfinder -d example.com | httpx -silent

Output

Subdomains, certificate data, public DNS records, and archived URLs.

Tips

Start passive first so you do not send unnecessary traffic to the target.

Phase 2 — Subdomain Enumeration

Find all subdomains related to the target domain. Subdomains often expose staging, admin, API, and testing environments.

Recommended Tools

  • Subfinder
  • Amass
  • Assetfinder
  • Chaos

Example Pipeline

subfinder -d example.com -silent | dnsx -silent

Output

A list of discovered subdomains.

Tips

Use multiple passive sources and merge results to get better coverage.

Phase 3 — Active Probing & Verification

Check which discovered hosts are actually alive. This removes dead entries and helps you focus on real web services.

Recommended Tools

  • httpx
  • gowitness
  • nmap

Example Pipeline

cat subdomains.txt | httpx -title -status-code -tech-detect

Output

Live hosts, HTTP status codes, page titles, technologies, and screenshots.

Tips

Focus only on live hosts so later steps stay faster and cleaner.

Phase 4 — Technology Fingerprinting

Identify the technologies used by the target, such as CMS, framework, web server, JavaScript libraries, and backend platforms.

Recommended Tools

  • WhatWeb
  • Wappalyzer
  • BuiltWith

Example Pipeline

whatweb https://example.com

Output

Technology stack details such as server type, framework, and plugins.

Tips

Technology data helps you guess likely weak points and known CVEs.

Phase 5 — Content & Directory Discovery

Discover hidden files, folders, and panels that are not directly linked from the UI. These often include backups, admin pages, and forgotten endpoints.

Recommended Tools

  • ffuf
  • feroxbuster
  • dirsearch

Example Pipeline

ffuf -u https://example.com/FUZZ -w wordlist.txt -fc 404

Output

Directories, files, hidden panels, and backup content.

Tips

Use extensions like .php, .txt, .bak, and .js for better results.

Phase 6 — URL & Endpoint Discovery

Collect URLs from crawlers and historical sources to find old APIs, forgotten pages, and hidden parameters.

Recommended Tools

  • katana
  • gau
  • waybackurls
  • hakrawler

Example Pipeline

gau example.com | sort -u

Output

A large list of URLs and endpoints from current and historical sources.

Tips

Remove static assets like images, fonts, and CSS to keep only useful URLs.

Phase 7 — JavaScript & Secrets Analysis

Analyze JavaScript files for hidden endpoints, API keys, tokens, and internal references that are not visible in the page source.

Recommended Tools

  • SecretFinder
  • jsluice

Example Pipeline

cat js_files.txt | xargs -I@ curl -s @ | jsluice urls

Output

Secret patterns, URLs, endpoints, and sensitive strings from JavaScript files.

Tips

Always review minified JS files because they often hide useful strings.

Phase 8 — Parameter Discovery

Find hidden GET, POST, JSON, and XML parameters. These are often the entry points for IDOR, XSS, SQLi, and SSRF testing.

Recommended Tools

  • Arjun
  • ParamSpider

Example Pipeline

arjun -u https://example.com/search

Output

Discovered parameter names and request variants.

Tips

Test parameters on endpoints where user input is likely accepted.

Phase 9 — Vulnerability Scanning

Use automated scanners to check for common issues, misconfigurations, and known CVEs after recon is complete.

Recommended Tools

  • Nuclei
  • SQLMap
  • Dalfox
  • Nmap
  • Ghauri

Example Pipeline

nuclei -l live_hosts.txt -tags cve,misconfig -severity critical,high

Output

Potential vulnerabilities, misconfigurations, and exposure findings.

Tips

Use scanners only after you have live hosts and useful endpoints.
