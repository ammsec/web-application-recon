Phase 2 — Subdomain Enumeration

Expand the attack surface beyond the main domain. Dev, staging, api, and admin subdomains often exist outside the primary site — and they're frequently less hardened.

Why this phase matters

The more subdomains you find, the bigger the attack surface. This phase runs in two parts: passive discovery pulls known subdomains from third-party sources with zero contact to the target, while active brute forcing checks for ones that aren't publicly indexed anywhere.

Part A — Passive Subdomain Discovery

Subfinder Go · Passive

What it does: Pulls subdomains from 50+ passive sources — Shodan, Censys, VirusTotal, SecurityTrails, and more. No request ever reaches the target directly.

GitHub ↗

Installation

go install -v github.com/projectdiscovery/subfinder/v2/cmd/subfinder@latest

# Verify
subfinder -version

API Keys Setup (provider-config.yaml)

File location: ~/.config/subfinder/provider-config.yaml

# First run subfinder once to generate the config file
subfinder -d example.com

# Then edit the config file
nano ~/.config/subfinder/provider-config.yaml
# ~/.config/subfinder/provider-config.yaml
# Only fill in the ones you have keys for — leave the rest as []
bevigil: [YOUR_BEVIGIL_KEY]
builtwith: [YOUR_BUILTWITH_KEY]
censys: [API_ID:SECRET]
certspotter: [YOUR_CERTSPOTTER_KEY]
chaos: [YOUR_CHAOS_KEY]
fullhunt: [YOUR_FULLHUNT_KEY]
github: [YOUR_GITHUB_TOKEN]
intelx: [2.intelx.io:YOUR_INTELX_KEY]
redhuntlabs: [https://reconapi.redhuntlabs.com/community/v1/domains/subdomains:YOUR_KEY]
securitytrails: [YOUR_SECURITYTRAILS_KEY]
shodan: [YOUR_SHODAN_KEY]
virustotal: [YOUR_VIRUSTOTAL_KEY]
whoisxmlapi: [YOUR_WHOISXMLAPI_KEY]
zoomeyeapi: [YOUR_ZOOMEYE_KEY]
# NOTE: BinaryEdge shut down (March 2025), BufferOver is inactive

Usage

# Basic scan
subfinder -d target.com

# Save to file
subfinder -d target.com -o subdomains.txt

# Use all sources (needs API keys)
subfinder -d target.com -all -o subdomains.txt

# Multiple domains
subfinder -dL domains.txt -o subdomains.txt

# Silent mode — just the results
subfinder -d target.com -silent

# JSON output
subfinder -d target.com -oJ -o subdomains.json

# List available sources
subfinder -ls

Part B — Active Subdomain Discovery (DNS Brute Force)

Wordlist-based brute forcing catches subdomains that passive sources miss. This is active — requests do reach the target.

dnsx Go · Active

What it does: Resolves and validates subdomain lists to confirm which ones actually exist. Also returns CDN and ASN info.

GitHub ↗

Installation

go install -v github.com/projectdiscovery/dnsx/cmd/dnsx@latest
dnsx -version

Usage

# Resolve Subfinder's output
subfinder -d target.com -silent | dnsx -silent

# Resolve from a file
dnsx -l subdomains.txt

# All DNS records
dnsx -l subdomains.txt -recon

# With CDN and ASN info
dnsx -l subdomains.txt -cdn -asn

# Custom resolvers (faster)
dnsx -l subdomains.txt -r 1.1.1.1,8.8.8.8

# JSON output
dnsx -l subdomains.txt -json -o dns_results.json

# Wordlist-based brute force
dnsx -d target.com -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-20000.txt
Amass Go · Passive + Active

What it does: Combines passive and active enumeration — certificate transparency, DNS brute force, and API integrations. Slower than Subfinder but more thorough.

GitHub ↗

Installation

go install -v github.com/owasp-amass/amass/v4/...@latest
amass version

Usage

# Passive only — safe, no direct contact
amass enum -passive -d target.com

# Active + passive
amass enum -d target.com

# Save to file
amass enum -d target.com -o amass_subdomains.txt

# Intelligence gathering (OSINT)
amass intel -whois -d target.com
Puredns Go · Active

What it does: Uses Massdns for high-speed DNS brute forcing — can check millions of subdomains in minutes.

GitHub ↗

Installation

# Step 1: Install Massdns (dependency)
git clone https://github.com/blechschmidt/massdns.git
cd massdns
make
sudo make install
cd ..

# Step 2: Install Puredns
go install github.com/d3mondev/puredns/v2@latest

# Step 3: Set up resolvers
mkdir -p ~/.config/puredns
curl -s https://raw.githubusercontent.com/trickest/resolvers/main/resolvers.txt -o ~/.config/puredns/resolvers.txt

Usage

# Brute force with a wordlist
puredns bruteforce /usr/share/seclists/Discovery/DNS/subdomains-top1million-20000.txt target.com

# Resolve an existing list
puredns resolve subdomains.txt

# Save output with custom resolvers
puredns bruteforce wordlist.txt target.com -r ~/.config/puredns/resolvers.txt -w valid_subdomains.txt
