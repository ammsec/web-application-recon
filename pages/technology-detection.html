Phase 4 — Technology Fingerprinting

Identify the frameworks, CMS, server software, and JS libraries a target is running. Knowing the exact stack turns a generic scan into a targeted one.

Why this phase matters

Once you know what a target is built on, you can go straight to the vulnerabilities that matter. Running WordPress? Look for WordPress-specific bugs and outdated plugins instead of wasting time on generic checks that don't apply.

Wappalyzer Browser Extension · Easiest

What it does: Installs as a browser extension — visit any site and it instantly shows the detected tech stack in the toolbar. No setup, no commands, works passively as you browse.

wappalyzer.com ↗

Install: search "Wappalyzer" in the Chrome or Firefox extension store.

WhatWeb CLI

What it does: Analyzes server headers, HTML, and cookies from the command line to identify the technology stack — useful for scripting against many hosts at once.

GitHub ↗

Installation

sudo apt install whatweb

Usage

# Basic scan
whatweb https://target.com

# Verbose output
whatweb -v https://target.com

# Multiple targets from a file
whatweb -i live_hosts.txt --log-brief=results.txt

# Aggression level (1-4, higher = more requests)
whatweb -a 3 https://target.com
